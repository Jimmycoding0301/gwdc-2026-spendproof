### 规则报告的绿灯具体意味着什么

报告分别列出错误放行、错误拦截、结论一致及隔离记录，详情展示逐项检查变化。候选从空账本按自己的允许结果重新累计，观察后续提案是否受影响；闸门按允许 / 拦截结论判定，不等于代码、金额和全部检查字段完全相同。SDK 历史回归则固定原上下文、比较更细的判断结果。

历史记录若无法由基准重现，会进入隔离项而不是被候选规则重新生成答案；隔离数量必须留在展示中。没有有效基准时不能报告通过。

“应用正确规则并重跑”只切换这次报告的候选，不写回事故、部署引擎或执行付款。两阶段之间事故集改变时，应重新运行，避免用不同数据组成红绿对照。本机没有历史时使用明确标为 fixture 的演示案例；已有历史没有触发费用故障时，故障候选不一定亮红灯，应先准备一条费用事故。

### 九个边界与只读收据

九个边界包括预算恰好够、少 1 micro-USDC、截止前 1 秒、恰好到期、截止后 1 秒、同商户换地址、移出商户许可、重复业务换报价 ID、用户停止。生成器先构造可解释的合成允许基线，再逐项改变条件；页面保留条件调整说明。“全部符合预期”包括正确拦截，不意味着全部提案获准。

收据隐藏任务正文、原业务单号、自由描述、日志和错误详情；保留金额、时间、演示商户与地址用于规则复算。原始证据、脱敏证据和收据各有明确摘要。浏览器一致性通过且存证为 `confirmed`、摘要内容匹配、关联当前原始证据，才能显示“链上已核验（服务端 RPC）”；浏览器没有自己重新查链，也不能从脱敏副本独立证明隐藏原文或用户授权真实。

## 启动与可复现演示

从项目根目录运行：

```bash
npm ci
npm run dev
```

网页 `http://127.0.0.1:5173`，API `127.0.0.1:8787`。无密钥时选择 fixture，可完成规则、红绿、边界、收据与回归演示；真实 Kiln 需后端 `.env` 配置并重启，测试链另需专用测试钱包和测试 ETH。`npm start` 只启动 API。

不启动网页也能展示 SDK：

```bash
node --import tsx examples/sdk-regression.ts --unsafe-omit-fees
node --import tsx examples/sdk-regression.ts
```

第一条是预期失败的红灯（退出码 1），第二条正确规则通过（退出码 0）；9 个边界加 2 条固定历史记录，全程无模型请求和付款。GitHub Actions 的远端运行需要先提交推送仓库，不能用本地结果冒充远端 CI 记录。
