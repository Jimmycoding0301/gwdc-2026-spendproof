# SpendProof · GWDC 2026 比赛计划

记录日期：2026-09-27；模型与产品流程更新：2026-09-28，时区 KST（UTC+9）。项目以 **FuriosaAI × Bricksum：会花钱 Agent 的控制与记录**为主方向。以下是当前产品和展示安排，不替代官方赛题或后续现场通知。

## 产品选择

一句话：**让 AI 供应商付款规则先在旧事故上亮红灯，修复后才发布。**

第一位用户是让 AI 帮忙处理跨境应付账款的小团队。典型事故是发票金额看似合规，但加服务费后超预算；供应商名称没变，收款钱包却被替换；同一发票也可能再次进入付款队列。开发者需要在发布规则前看清错误、修复并重放同一批事故。

本版聚焦两家演示供应商与确定性规则。钱包登记、含费预算、期限、发票去重、停止及审计是基础要求。当前五项主扩展均已有实现：测试链摘要闭环、规则发布影响报告与红绿对照、9 个合成边界、只读脱敏收据、TypeScript SDK / CI；本机“发票截图 → 授权草稿”作为工作入口。真实模型和一笔 Base Sepolia 零金额证据存证均已验收；供应商付款仍为模拟。

## 五个工作台页面与独立收据

| 屏幕 | 观众要明白的事情 | 演示证据 |
| --- | --- | --- |
| 授权与运行 | 用户可从日常工作截图形成待确认草稿；模型给提案，代码在模拟执行前判断 | 本机 OCR 原文依据与置信度、明确填入动作、费用超预算及商户地址替换阻止 |
| 规则发布 | 一次规则修改会不会重新放过旧事故 | 固定历史期望、故障候选红灯、正确规则绿灯、隔离记录，以及 9 个合成边界 |
| 事故回放 | 新规则可以作用于原提案，不必重新花钱或重新询问模型 | 原始决定与新决定并排，原记录不变 |
| 证据与测试 | 一次事故可以交给别人复核，也能检查未来规则改动 | 证据下载、核验结果、加载当前引擎运行回归文件 |
| 接入状态 | 区分已配置与已验证，显示真实服务返回的用量 | fixture / Kiln、模型名、token 及测试链验收状态 |
| 独立只读收据页 | 接收方可以复算公开快照，知道哪些内容已隐藏 | 固定摘要链接、模拟标签、浏览器核验、原始 / 脱敏摘要及链上记录；可打印为 PDF |

启动：项目根目录执行 `npm ci`、`npm run dev`，打开 `http://127.0.0.1:5173`（API 为 `127.0.0.1:8787`）。`npm start` 只开 API。无需密钥的现场备份使用 fixture；不要切换到未配置的 Kiln 后把失败当演示完成。

## 3 分钟视频脚本

| 时间 | 画面与动作 | 旁白重点 |
| --- | --- | --- |
| 0:00–0:15 | 粘贴一张采购截图，展示四项识别结果与原文依据，再点“一键填入授权” | “财务每天收到的是聊天和截图；先把抄表动作省掉。识别只生成草稿，不会自动运行或付款。” |
| 0:15–0:35 | 打开已保存的真实 Qwen 费用事故，指出商品加手续费超预算 | “模型可以挑服务，发布新规则时谁来确保旧事故不会再被放过？”真实推理与模拟付款标签同时可见 |
| 0:35–1:00 | “规则发布”点“运行故障候选”，展开错误放行的 5 USDC 含费提案 | “这个候选漏算手续费，同一份历史期望现在亮红灯。”同时保留隔离数量 |
| 1:00–1:20 | 点“应用正确规则并重跑”，展示相同事故集通过 | “恢复含费判断，可复现基准转绿；没有改写历史，也没有部署规则或付款。” |
| 1:20–1:45 | 点“生成 9 个边界案例”，展开预算少 1 micro-USDC、同名换地址 | “一次提案还能派生确定性的边界检查；绿色包含正确拦截。”明确这些是合成案例 |
| 1:45–2:20 | 打开只读收据，展示浏览器核验、模拟标签、摘要和实际链状态 | 只有成功回执与摘要匹配时才称链上核验通过；复制是本机链接，打印可交接 PDF |
| 2:20–3:00 | 预置终端运行 SDK 正确示例，展示 GitHub Actions 文件 | “9 个边界与 2 条固定历史案例可以在你的 CI 中跑。”工作流配置不等于已经远端运行；收尾强调实际采购仍模拟 |

开演前固定费用会话、确认两阶段使用同一事故集并预跑红绿。已有历史不含费用事故时不保证红灯；不要临场改历史期望来制造红绿结果。批量报告显示的是本机历史，边界案例则来自当前选中会话，两者数据范围不同。

SDK 终端备份不需要启动服务，故意错误候选应返回退出码 1，正确候选为 0：

```bash
node --import tsx examples/sdk-regression.ts --unsafe-omit-fees
node --import tsx examples/sdk-regression.ts
```

视频与日常开发推荐从项目根目录执行：

```bash
SPENDPROOF_ENGINE=./shared/policy.ts node --import tsx --test spendproof-*.test.mjs
```

不设置 `SPENDPROOF_ENGINE` 时，`node --test spendproof-*.test.mjs` 只执行导出时的内嵌规则快照，适用于离线复核，不能展示“当前代码没有回归”。故意忽略服务费的候选已经内置在发布报告与 SDK 演示中，不需要现场编辑真实规则文件。

进入 Final 后按赛事 FAQ 准备 5 分钟展示与 3 分钟问答。3 分钟视频不要塞入所有功能；重复业务单、停止、期限和错误响应留作备查或问答演示。

**测试链验收已完成一次：** 已使用独立测试账户在 Base Sepolia 提交证据摘要，交易 [`0x10f68d…8ce25a`](https://sepolia.basescan.org/tx/0x10f68d330eca7baca5cee9c4a74cdc4b7732a43933021f3db7e0297fb68ce25a) 在区块 `47411854` 成功确认。公开 RPC 已比对 chain ID、零金额自转和 calldata 中的证据 digest；重复提交返回同一哈希。它是证据摘要存证，不能用来宣称完成链上采购付款。
