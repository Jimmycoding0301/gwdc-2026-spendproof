# SpendProof 威胁模型与保证边界

版本：2026-09-28 本地原型，含规则发布报告、合成边界、只读收据与 SDK。

本文描述当前设计能够检查的内容与信任前提，不是安全审计报告。API 采购付款为 simulation；所有保证首先针对受控的单机原型流程。

## 资产与信任边界

| 对象 | 当前作用 / 假设 |
| --- | --- |
| 用户设定的 policy | 定义预算、允许商户、期限及任务；当前没有独立身份认证或授权签名体系 |
| 模型及模型输出 | 不受信任的提案来源；不能自行修改规则、宣布支付成功或提供权威商户登记信息 |
| 演示商户登记表 | 由应用代码管理 merchant ID 与 recipient 的绑定；演示地址不是实际收款商户 |
| 规则引擎 | 受信任代码，按整数金额和当前上下文判断提案 |
| Express 进程及本机文件 | 受信任的执行与保存环境；可访问它们的攻击者可能修改 policy、记录或代码 |
| Kiln | 可选远程推理服务；开启后，发送给模型的任务和上下文会离开本机 |
| Base Sepolia RPC / 测试账户 | 可选摘要存证通道；独立测试密钥会产生真实测试链交易并支付测试 gas |

当前 API 服务面向本机开发使用，不具备多租户隔离、生产级鉴权、账户权限管理或独立可信签名服务。将端口暴露给公网不会使这些能力自动存在。

## 要拦截的行为

| 场景 | 当前控制 | 限制 |
| --- | --- | --- |
| 服务费未计入导致超额 | `amount + fee + 本会话累计模拟支出` 与预算比较 | 不涵盖真实钱包余额、交易结算差异或另一个会话的支出 |
| 商户名字保留但地址替换 | 同时检查 merchant ID 允许范围和登记 recipient | 登记表本身被篡改、登记业务真实性不由此证明 |
| 过期任务继续提案 | 按 policy 有效期与执行时刻检查 | 依赖宿主时钟；离线重放使用保存/指定的上下文，不能证明过去的物理时间 |
| 重复处理同一业务单 | 对成功模拟记录中的 businessId 做会话内去重 | businessId 换名、跨会话重复、并发分布式结算需额外设计 |
| 停止后继续执行 | 每个提案检查停止状态 | 已发生的外部调用或未来真实结算不能通过这个开关撤销 |
| 模型返回负数、小数或异常金额 | 类型、整数及数值范围校验 | 合法数值可能仍是错误业务事实，需要上游证据 |
| 工具返回内容诱导模型改规则 | 模型只有提案能力，执行前再次走独立规则 | 不是通用提示注入检测器；不保证模型答案或外部数据内容正确 |

## 证据意味着什么

证据包的摘要可以发现文件与既定摘要不一致；规则复核可以发现提案与记录结果不一致，或相邻记录中的累计上下文不连贯。以上检查有助于复核事故和发现意外篡改。

**没有独立保存的可信摘要或签名时，攻击者可以同时修改记录并重算 SHA-256。** 一个自洽的新包仍可能通过内容摘要检查。规则核验也不能证明其中的报价、用户授权、时间戳或模拟交易对应真实外部事件。

可选测试链存证让某个摘要拥有外部链上记录。核验者仍需要确认实际 chain ID、交易回执及摘要内容与本地证据对应。链锚不证明数据真实，不证明 signer 是业务授权人，不证明任何 USDC 付款发生，也不能补上存证前缺失的原始事实。

未来若处理真实资金，需要独立的授权签名、可信商户来源、结算结果核验、交易幂等与未知状态恢复，而不是仅增加一个哈希字段。

## 重放与回归测试

重放读取保存的原提案，用另一个 policy 进行判断，不重新请求模型、不执行付款。它回答的是“这些相同提案在这些规则下会得到什么结果”，不能预测模型下一次是否会提出相同建议。

回归导出包含事故输入、预期判断和备用规则快照，支持两种不同保证范围的模式：

- **当前引擎模式（开发时推荐）**：`SPENDPROOF_ENGINE=./shared/policy.ts node --import tsx --test spendproof-*.test.mjs` 从执行命令时的工作目录解析模块路径，并调用该模块导出的 `evaluateProposal`。它可以发现当前规则与历史事故期望不一致的变动；显式设置无效路径、空值或缺失导出时应失败，不静默回退。
- **离线快照模式**：不设置 `SPENDPROOF_ENGINE`，执行 `node --test spendproof-*.test.mjs`。只复核导出时内嵌的规则，不检验未来应用实现。

脚本应清楚输出运行模式。两种模式都不会调用模型或付款。当前引擎测试通过，只证明给定案例在指定模块上满足保存的预期；预期本身仍需审查，也不能替代完整执行路径、并发和外部结算的集成测试。若规则有意改变，开发者需要审查期望差异，不应为了得到绿色结果直接覆盖历史事故。

原始事故应保持不变，重放结果单独记录。不要将重放中允许的提案加入真实采购或原会话的已付列表。

## 发布报告、合成边界与 SDK

发布报告用已保存的允许 / 拦截判断作对照，候选从空账本重新累计自己的允许结果，保留原始时间与停止状态，观察后续提案的影响。绿色只说明纳入案例的允许 / 拦截结论一致，不保证全部原因码或检查字段相同，也不修改或部署规则。SDK 历史回归是另一种检查：保持各条原始上下文，比较允许标记、原因码、含费金额及检查结果，不把候选结果带到下一条。

不可复现的历史基准会被隔离，不能当成通过项。红绿两阶段必须使用同一事故集；有意改变业务规则时，应另行审查并版本化预期，而不是覆盖旧事故来制造绿灯。

边界生成器从提案构造合成允许基线，再改变预算、期限、身份、重复标记或停止状态，输出 9 个有明确期望的案例。合成案例标明条件调整；它们不是新增授权、真实模型调用或付款证据。有限边界检查不保证覆盖并发、真实结算或任意恶意输入。

SDK 是本仓库源码，不是已发布包或不可信代码沙箱。自定义 evaluator 必须是受信任的同步纯代码；SDK 没有支付执行器或原子账本。CI 示例不加载本机凭据、不请求模型或链，仍不能代替真实接入的端到端验收。

## 只读收据与公开信息

收据对白名单字段建立单独脱敏快照，隐藏任务正文、原始业务单号、日志及错误详情，保留规则复算所需金额、时间和地址。原始证据、脱敏证据和收据本身的摘要不同，不能混用。服务端拒绝含已知配置密钥值的导出；脱敏不等于匿名化，时间、金额和公开地址仍可能关联到业务。

链接携带摘要并读取已保存的对应收据版本；若版本不存在，不能静默给出不同快照。当前链接只访问本机服务，没有自动公开托管或访问控制。打印 / 保存 PDF 只是浏览器输出，不是数字签名；接收方无法仅凭脱敏副本证明其与隐藏原文的完整对应关系。

“链上已核验”还要求浏览器检查通过、存证 `confirmed`、RPC 内容匹配、且摘要关联当前原始证据。该页面保存的是服务端 RPC 结果，浏览器自身没有重新查询链；其可信度依赖服务器及 RPC，可通过真实交易哈希独立复查。

## 本地存储、并发与恢复

`.data/` 是磁盘文件存储，当前按单机单进程使用。应单独验证并发启动、重复运行、写入中断、进程崩溃及停止时机；不能从正常流程演示推导出分布式 exactly-once 结算保证。

在没有真实支付适配器的版本中，账本的 `simulated` 状态只表示模拟执行完成，`blocked` 只表示本地规则拒绝。模拟记录没有 txHash；证据存证交易哈希属于另一个用途。

## 凭据与外部服务

- Kiln key、测试私钥保存在后端环境变量中，不能写入仓库、证据包、浏览器 bundle 或日志。
- 自定义 `KILN_BASE_URL` 会改变 API key 和请求内容的接收方；仅使用自己核实过的服务地址。
- Base Sepolia 功能默认关闭，仅 chain ID `84532` 可用；使用独立测试账户及测试资产。
- 模型错误和超时要如实显示；fixture 结果不能伪装成真实服务响应。
- 当前没有能耗传感器或 NPU 功率测量。真实 token usage 只能支持调用量统计。

## 本版不作出的保证

当前不声称生产资金安全、完整 AP2 或 x402 支付实现、不可否认授权、防全部提示注入、跨会话唯一付款、链上采购完成、数据真实、通过第三方审计或 NPU 节能效果。

这些边界应在界面、演示和提交材料中保持一致。开发与验证过程发现的新限制应补充到本文，而不是用模拟成功替代真实接入证据。
